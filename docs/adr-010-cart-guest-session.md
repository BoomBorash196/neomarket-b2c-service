# ADR-010: идентификация гостевой корзины

## Контекст

US-CART-03: корзина покупателя для гостя (без авторизации) и авторизованного
пользователя, с merge при логине. Нужно выбрать, как идентифицировать гостевую
корзину.

## Рассмотренные варианты

| Вариант | Совместимость с мобильными клиентами | Риск подделки идентификатора |
| --- | --- | --- |
| **`X-Session-Id` заголовок** (выбрано) | Высокая: любой HTTP-клиент (мобильное приложение, SPA, curl) ставит заголовок без cookie-инфраструктуры | Средний: клиент генерирует UUID сам; подделка чужой сессии возможна, но сессия содержит только корзину, ущерб ограничен |
| **Cookie** | Низкая для нативных мобильных клиентов (нужен cookie-jar, CSRF-защита) | Низкий при HttpOnly+Secure+SameSite, но усложняет кросс-доменные сценарии |
| **Временный JWT (гостевой токен)** | Высокая | Низкий (подпись проверяется), но требует выдачи и ротации токенов, усложняет гостевой flow |

## Решение

Выбран **`X-Session-Id`**: гостевая корзина keyed по UUID сессии из заголовка.
Это совместимо с мобильными клиентами без cookie-инфраструктуры и не требует
выдачи JWT. Риск подделки ограничен тем, что корзина не содержит PII и не
резервирует товар (lazy reserve при checkout). Merge при логине: `MAX(guest_qty,
auth_qty)` по SKU, гостевые строки не удаляются (идемпотентность).

## Последствия

* Плюс: простая интеграция для любых клиентов, без cookie/JWT-инфраструктуры.
* Плюс: merge детерминированный и идемпотентный.
* Минус: идентификатор генерируется клиентом — возможна подделка чужой
  гостевой корзины (ограниченный ущерб: только корзина, без PII и резерва).
* Минус: при потере сессии гостевая корзина недоступна — стандартное поведение
  для гостевых корзин.
